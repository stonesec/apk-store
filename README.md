# فروشگاه رایگان اپلیکیشن اندروید (نسخه GitHub Pages)

کاملاً رایگان، بدون سرور. سایت روی GitHub Pages، فایل‌های APK در بخش Releases همین مخزن.

## راه‌اندازی (فقط یک بار)

1. **مخزن باید Public باشد.** GitHub Pages رایگان فقط برای مخزن عمومی کار می‌کند. یک مخزن جدید Public بسازید (مثلاً `apk-store-site`) و **محتوای** این پوشه را داخلش آپلود کنید (Add file ← Upload files).
2. فایل `apps.json` را باز کنید (مداد ✏️) و در خط `"repo"` به‌جای `USERNAME/REPO` بنویسید `نام‌کاربری‌شما/نام‌مخزن`. مثلاً `ali/apk-store-site`. بعد Commit changes.
3. در مخزن: **Settings ← Pages** ← در Source گزینه **Deploy from a branch** ← Branch: `main` و پوشه `/ (root)` ← Save.
4. بعد از ۱ تا ۲ دقیقه آدرس سایت در همان صفحه نمایش داده می‌شود: `https://نام‌کاربری.github.io/نام‌مخزن/`

## افزودن برنامه جدید

1. **تصاویر:** در مخزن وارد پوشه `images` شوید ← Add file ← Upload files. برای هر برنامه یک پوشه بسازید (مثلاً `my-app`) و آیکون و اسکرین‌شات‌ها را بگذارید. نام فایل‌ها انگلیسی و بدون فاصله باشد (`icon.png`، `1.png`).
2. **فایل APK:** در صفحه مخزن، سمت راست روی **Releases** ← **Create a new release** ← در Tag یک نام بنویسید (مثلاً `my-app-1.0.0`) ← فایل APK را در بخش «Attach binaries» بکشید ← **Publish release**.
   نام فایل APK را قبل از آپلود انگلیسی و یکتا کنید، مثل `my-app-1.0.0.apk`.
3. **معرفی در سایت:** `apps.json` را ویرایش کنید. بلوک برنامه نمونه را کپی کنید و مقادیر را عوض کنید. `"file"` باید **دقیقاً** هم‌نام فایل APK در Releases باشد. حجم و تعداد دانلود خودکار از GitHub خوانده می‌شود.
4. Commit changes بزنید، ۱ تا ۲ دقیقه صبر کنید و سایت را تازه کنید.
5. **بررسی:** آدرس سایت را با `#/check` باز کنید. هر نسخه‌ای که فایلش پیدا نشود با رنگ قرمز نشان داده می‌شود و در سایت نمایش داده نمی‌شود (لینک شکسته نداریم).

## انتشار نسخه جدید

یک Release جدید با APK جدید بسازید. در `apps.json` داخل `"versions"` یک بلوک تازه اضافه کنید (بین بلوک‌ها ویرگول بگذارید) با `"code"` بزرگ‌تر از نسخه قبلی. نسخه با بزرگ‌ترین code دکمه اصلی دانلود می‌شود.

## نکات و محدودیت‌ها

- **تعداد دانلود** همان عددی است که خود GitHub برای هر فایل ثبت می‌کند و تا چند دقیقه ممکن است به‌روز نباشد. ربات‌ها هم ممکن است شمرده شوند.
- اگر سایت خالی ماند، معمولاً در `apps.json` ویرگول یا گیومه جا افتاده است. محتوا را در jsonlint.com بررسی کنید.
- پنل مدیریت ندارد؛ مدیریت با ویرایش `apps.json` و Releases انجام می‌شود و فقط شما به مخزن دسترسی ویرایش دارید.
- هر فایل داخل Releases کمتر از ۲ گیگابایت باشد.
- سئو ضعیف‌تر از نسخه سروری است، چون صفحه‌ها با جاوااسکریپت ساخته می‌شوند (عنوان و داده ساختاریافته هر برنامه تنظیم می‌شود ولی نقشه سایت خودکار ندارد).
- سایت برای خواندن Releases از API عمومی GitHub استفاده می‌کند که محدودیت تعداد درخواست دارد. اگر ترافیک خیلی زیاد شد ممکن است موقتاً پیام خطا ببینید.
- آدرس `github.io` برای شروع کافی است. بعداً می‌توانید دامنه اختصاصی را در Settings ← Pages وصل کنید.
